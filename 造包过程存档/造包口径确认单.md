# 造包口径确认单（P1 产出）

> 依据总控 Prompt §4.1。问的是**造包口径**（技能包怎么造），不是写书口径（小说怎么写，后者由 ZIP 内确认助手在 L3 承担）。
> 本单逐项记录「提问 / 用户答复 / 对后续设计的约束」。P1 门禁：10 项均有记录（含“由你裁定”也算有效），且第 6 项授权范围清晰。
> 本单为造包过程文件，最终随包交付的 `README.md` 裁决记录将引用本单裁决编号。

## 一、逐项记录

### P1-1 目标成品体量区间（§4.1.2-1）
- **提问**：偏 10–30 万 / 30–100 万 / 100–200 万字？是否需要包内预置对应的分卷粒度与状态压缩强度？
- **用户答复**：全覆盖自适应（卡片选项“全覆盖”）。
- **对后续设计的约束**：包内必须预置三档粒度与压缩强度（10–30 万 / 30–100 万 / 100–200 万），正文会话按实际目标自动切换；字数累计器、卷/部/章三级切分、滚动摘要压缩频率均分档给出（§14.1）。硬上限 2,000,000 字不变（§1.15）。

### P1-2 题材与形态倾向（§4.1.2-2）
- **提问**：偏网文连载 / 出版长篇 / 类型文学 / 严肃文学 / 混合？这会影响节奏规范、章节卡颗粒度与去 AI 味的严格度。
- **用户答复**：混合 / 全覆盖（卡片选项“混合”）。
- **对后续设计的约束**：包内分形态给规范（网文连载 / 出版长篇 / 类型文学各一套节奏与章节卡颗粒度），确认助手在 L3 按用户实际选择启用对应档，不预设单一形态。

### P1-3 笔样可提供性（§4.1.2-3）
- **提问**：是否已有用户笔样可提供？若暂无，包内是否要内置“笔样补采与冷启动风格推定”流程？
- **用户答复（自定义）**：“这个笔样是每次创作小说，这个负责创建小说的那个 GLM 问的，不是这个预制的，也不能预制”。
- **对后续设计的约束**：包内**不预置**任何具体笔样文本；只内置采集流程（首轮必问 + 冷启动 300–800 字补采 + 风格指纹初表核对），由 L3 确认助手在每次开新书时向用户采集。笔样与参考书分栏存放、不得混用（§15.1）。

### P1-4 风格相似严格度（§4.1.2-4）
- **提问**：“与用户风格相似”的严格度：神似即可，还是需逐项指纹比对并出比对表？
- **用户答复**：神似即可（卡片选项）。
- **对后续设计的约束**：包内保留风格指纹表（§15.2）作为比对工具，但验收以**抽样比对**为准，不强制每轮逐项出《风格比对表》；严格档（逐项出表）作为可选升级路径保留，用户在 L3 可随时加严。去 AI 味冲突裁决（§15.4）不变：以指纹“必须像”项为准。

### P1-5 检索联网（§4.1.2-5）
- **提问**：检索助手是否允许联网多轮检索？若部署环境不能联网，是否要内置“离线资料包 + 本地归纳”降级链路？
- **用户答复**：允许联网多轮检索（卡片选项）。
- **对后续设计的约束**：检索助手按 §10.3 多轮联网检索执行（≥2 轮，留痕）；离线降级链路仅作兜底说明写入规范，不作为主路径。

### P1-6 授权范围（§4.1.2-6，门禁关键项）
- **提问**：是否授权自主裁定会话数量、命名、顺序与后续工序（含是否单设去 AI 味、是否合并润色）？请明确授权范围。
- **用户答复（自定义）**：“首先那个指令文件 2000 字以内是第一个，记忆文件是第二个，也是 2000 字以内。然后第三个是作者一，然后主要就是我说的那个，首先立项，然后给出搜索文件，然后写作二是检索的，也就是搜索助手专门负责搜索的。然后就是说第一个立项的话，现在不需要再负责什么世界观这种撰写了，都交由下几个会话来进行，然后剩下的那些个数量啥的完全由你来裁定，但是你裁定完之后必须得发问题来询问我这个行不行，需要不需要什么修改啥的。”
- **对后续设计的约束**：
  1. 根级顺序确认：01=自定义指令、02=长期记忆、03=作者一（立项/确认总控）。与 §2.08 消歧一致。
  2. 作者二=检索助手（单列，§10）。
  3. **作者一职责变更**：只做立项（多轮确认）+ 检索需求文件，**不再负责世界观等设定撰写**，设定族交由后续会话承担（见裁决 C-01）。
  4. 授权 = **完全授权 + 提案确认门禁**：其余会话的数量、命名、顺序、合并拆分完全由造包 Agent 裁定，但 P3 提案必须发问题询问用户行不行 / 需不需要改，用户确认前不得生成 ZIP 内文件（§4.3.4）。

### P1-7 验收偏好（§4.1.2-7，补问）
- **提问**：对“最顶级 / 超详细”的验收偏好：更看重规范覆盖密度，还是更看重可直接照抄的模板与示例？
- **用户答复**：都要，密度在前模板在后（卡片选项）。
- **对后续设计的约束**：每份规范五层齐全（§8.3）优先保证覆盖密度；模板必须填空即用（§8.5），示例正反例齐全（§8.3-L4）。宁可多拆文件，不删条款（§3.3）。

### P1-8 交付命名、目录风格、教程三件套（§4.1.2-8，补问）
- **提问**：交付命名、目录风格、是否需要额外的使用教程 / 导入检查单 / 故障排查表？
- **用户答复**：
  - 命名/目录：中文名 + 作者一/二/三（卡片选项）。
  - 教程三件套：全部都要（教程 + 检查单 + 排查表），但**不要在 ZIP 包里，单独放在外面**（自定义回复）。
- **对后续设计的约束**：
  1. ZIP 名用中文（如 `GLM多会话长篇小说创作技能包.zip`，以 P3 提案为准）；文件夹用 `作者一`、`作者二`……（见裁决 C-02）。
  2. 三件套外置：放在仓库内、ZIP 外单独存放；ZIP 内 `README.md` 只做索引指向，不内嵌三件套全文（见裁决 C-03）。§5.3 能力不减，仅存放位置变更。

### P1-9 内容边界（§4.1.2-9，补问）
- **提问**：是否存在必须规避的内容边界、平台规则、受众禁忌，需写进全局指令？
- **用户答复（自定义）**：“避开女频，主攻男频。”
- **对后续设计的约束**：受众边界 = 男频向，避开女频写法。写入 `01_自定义指令.md` 一条纪律（受众边界），并在确认助手全量确认表、节奏规范、去 AI 味严格度中落地；但不得在 01 中写死具体题材/人物/情节（§6.3），具体题材仍由 L3 每次确认（见裁决 C-04）。

### P1-10 返工轮次与确认方式（§4.1.2-10，补问）
- **提问**：若《工序设计提案》与用户预期不符，允许的返工轮次与确认方式？
- **用户答复**：不限轮次，逐条批注改（卡片选项）；结合 P1-6“提案后发问题问行不行 / 需不需要改”。
- **对后续设计的约束**：P3 提案后以问题形式请用户确认；用户提修改 → 回到 P3 重出提案，不限轮次（§4.3.4）；确认时间必须晚于提案、早于任何 ZIP 文件生成，并在构建日志留痕。

## 二、裁决记录（供 ZIP 根 README 引用）

- **C-01 作者一职责变更**：总控 Prompt §9.5/§11 原设“第一个据此创作大纲/人物/世界观”，用户 P1-6 明确改为“作者一只做立项 + 检索需求，设定族交后续会话”。按 §20.C 以用户本次答复为准。P3 提案将重排设定族归属（新设设定会话或由正文前置会话承担），并附四段式推演。
- **C-02 命名**：用户选“中文名 + 作者一/二/三”。§5.2/§3.6 授权 P3 裁定命名，本裁决即用户直接裁定，P3 不再另选。编号不用两位补零。
- **C-03 三件套外置**：§5.3 原设三件套在 ZIP 内，用户 P1-8 要求单独放在外面。能力不减，仅位置变更：仓库内 `外置文件/` 存放，ZIP 内 README 索引指向。§17 验收中“三件套齐全”按仓库口径判定。
- **C-04 男频边界**：§6.3 禁止 01 写具体题材，用户 P1-9 要求写受众边界。裁决：01 只写一条受众纪律（男频向、避开女频写法），不写具体题材/人物/情节；具体题材由 L3 确认助手每次确认。既满足用户边界，又不破坏 01 的“只写纪律”定位。
- **C-05 笔样不预制**：用户 P1-3 明确笔样由 L3 每次采集、不能预制。与 §9/§15 一致，无冲突，记为设计约束。
