# P6/1.1.0 修订后的验证报告

> 本报告替代1.0版报告中的“全部通过”结论。技能包静态文件检查、工具检查、真实GLM平台行为、写作效果是不同类别；不能由文件存在或模型自检互相代替。

## 1. 验证范围与已知限制

- 对象：此目录下的技能包源文件、`manifest.json`与配套ZIP。
- 统计口径：Unicode非空白码点数，标点计入；单章统计仅针对纯正文文件。此口径为本项目规则，不保证与平台/出版计数相同。
- **未验证**：发布者没有真实GLM项目账号可供部署测试；未实测不同模型版本、账户/套餐、项目文件区容量、跨会话读写、目录层级、指令/记忆注入或完整小说质量。
- **不可由工具证明**：人物声音是否真实、剧情是否优秀、审计是否独立、模型是否始终遵守指令。相关人工判断需结合原文证据并由用户抽检。
- `manifest.json`逐文件字节数、码点数、SHA-256是完整性证明，不是内容可运行或创作质量证明。

## 2. 自动检查（可重复）

命令：

```bash
python 工具/构建与校验.py build
python 工具/构建与校验.py verify   # 文件/ZIP/manifest完整性
python 工具/构建与校验.py lint     # 有限语义一致性，不是文学审阅
python 工具/validate_state.py 项目状态索引.json
python 工具/测试工具.py
```

预期：构建脚本创建manifest和ZIP；verify核验源目录与manifest、UTF-8/BOM、01/02字符上限、作者必需文件、SHA-256、ZIP CRC、根目录顺序和外置指南排除。测试工具覆盖码点口径、2500–4000边界、虚构示例长度、状态枚举与stale放行负例、摘要覆盖缺口、段落重复提示、有限语义lint、ZIP完整性，以及临时目录中的可重复构建（断言源manifest/ZIP不变）。状态schema、摘要结构/覆盖和重复检测各自仅在定义范围内工作；脚本不验证摘要/剧情语义正确性，也不证明模型遵循规则或平台跨会话能力。

## 4. 真实部署冒烟测试状态

发布者没有用户项目权限，部署手册测试表未由发布者执行。因此状态为**未验证/待使用者在目标账号填写**，不是通过。使用者应分别验证文件上载、另一会话读取/保存回读、目录保留或拍平映射、01/02注入与字数脚本。任一关键项失败时应暂停，使用人工文件导出/重命名方案或确认该平台不适用。

## 5. 验收结论

本报告不宣称整个创作系统或GLM平台“验收通过”。`verify`、`lint`和工具回归测试须分别报告：前者是完整性，第二者只覆盖列出的语义不变量，后者仅验证显式测试用例；三者不能替代真实账号E2E或文学判断。字数/重复检测只对指定文本文件的统计范围生效。其他项目须按证据分别标记“已检查/未验证/不适用/失败”。
