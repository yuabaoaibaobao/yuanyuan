# 清言平台适配说明（1.2.0 新增）

> 证据边界：本文依据2026-11-24可得的公开产品资料，以及一次在真实GLM多会话平台（清言AgentMore，GLM系列模型）内的实测（见仓库`维护记录/第五轮GLM平台实测与优化记录.md`）。它不构成任何平台能力认证；具体限额、入口与行为随产品版本/账号/套餐变化，一律以`部署与运行手册.md`冒烟测试在本账号的实测为准。

## 1. 两种部署形态

### 形态A：智谱清言网页「项目空间」（本包原始目标）

- 项目文件区作为跨会话共享文件区使用；项目内多个会话读取同一批文件，须先跑部署手册冒烟测试第2步验证。
- `01_自定义指令.md`、`02_长期记忆.md`分别贴入项目自定义指令与长期记忆位置。包内≤2000码点是自设保守预算，不是平台硬上限；若平台限制更紧，按手册压缩背景描述而保留门禁条款。
- 工具按本地Python为权威路径运行（见第3节）。

### 形态B：清言 AgentMore／工作区型多智能体

- 文件保存在共享工作区，跨会话、跨智能体天然可见，等价于"项目文件区"且通常保留目录层级；拍平映射仅作降级备用。
- 平台自带原生代码执行环境：`工具/`脚本可直接运行，无需粘贴正文（消除形态A的粘贴截断风险）。
- 多智能体群组通常有成员上限（公开资料为约5个）：按第2节把十位作者映射到角色位。
- 群组内的智能体同样不会自动互调包内作者职责；由用户在群组中切换、指派并执行门禁批准。公共/私密文件区划分以平台为准，笔样等敏感材料放私密区或不上传。

## 2. 十作者→五角色位映射（形态B）

| 角色位 | 承载作者 | 合并理由 |
|---|---|---|
| 位1 治理 | 作者01、02 | 立项/口径与长期记忆、审美，低频 |
| 位2 设定与规划 | 作者03、04 | 设定锁定→章节卡为同向流水 |
| 位3 正文 | 作者05 | 独立高频，正文唯一写入者不合并 |
| 位4 质量轨道 | 作者06、07、08 | 润色、双审、窗口审计同属质检 |
| 位5 收口 | 作者09、10 | 定稿放行与质量账本 |

约束：角色位内切换作者时仍按包协议写交接包、更新状态索引；同一文件唯一写入者规则不变；门禁批准权始终在用户。

## 3. 工具的三条运行路径

| 路径 | 适用场景 | 说明与限制 |
|---|---|---|
| 本地 Python 3.9+ | 默认权威路径 | `python 工具/字数统计.py <文件> --chapter-range`；SHA-256、ZIP与manifest校验只能在此完成 |
| 网页会话代码解释器 | 无本地环境的形态A | 把脚本与正文文本粘贴运行；超长文本可能被截断或转义，运行后须核对输出行数与码点量级是否合理；模型自报不算证据，只有脚本stdout算 |
| 浏览器计数器 `工具/字数统计.html` | 手机/无Python应急 | 本地打开、不发网络请求；语义镜像Python版（front matter/标题行/闭合HTML注释剥离、未闭合告警拒绝门禁计数）；空白字符判定与Python存在极小差异，权威复算仍以Python为准 |

## 4. 上下文压缩防线（实测观察）

- 实测环境（清言AgentMore，GLM系列模型）在长会话、多轮工具调用后，会对早期上下文做自动摘要/压缩，以占位符替代原文。压缩不预告、不询问。
- 后果：只存在于聊天中的约束、版本号、文件路径会随压缩静默丢失；已落盘文件不受影响。
- 对策（已同步写入`01_自定义指令.md`【压缩防线】）：
  1. 每完成一个动作块，立即把产物写入文件并更新状态索引/JSON；
  2. 跨批次恢复只认最近落盘检查点，不从聊天推断；
  3. 长会话每完成一个双章批次，重读01的门禁条款（约1千码点，代价可忽略）；
  4. 新开/续场会话使用第5节引导块。
- 百万级长上下文不改变上述结论：窗口大不等于逐字保真，压缩/摘要仍可能静默替换细节；文件真值是唯一廉价且可校验的锚点。

## 5. 会话开场引导块（通用模板）

新开或续接任一作者会话时，用户粘贴以下块（尖括号内容按项目实际替换）：

```text
【项目】《<书名>》；状态索引：项目工作区/项目状态索引.md（当前版本<vX.Y>）
【本次身份】作者<NN>；请先完整执行 作者<NN>/会话指令.md 的开工读取清单，逐项登记文件名/版本/状态；无法读取的文件列为阻断，不得凭记忆或"参考前文"补全。
【检查点】以索引"当前检查点"栏为准，仅按其推进；不读聊天历史。
【本轮目标】<唯一动作，如：产出第003/004章章节卡并交作者05>
【门禁提醒】01优先级、字数口径、用户批准项未变；发现冲突先停下询问用户。
```

## 6. 冒烟测试在两种形态下的差异

- 形态A：完整执行部署手册冒烟测试表全部行。
- 形态B：文件区跨会话读取通常由平台能力保证，但注入回执、字数工具、试写/审计流程三行仍须实测，并把结果记入`project_state.json`的`injection_receipts`与状态索引。
