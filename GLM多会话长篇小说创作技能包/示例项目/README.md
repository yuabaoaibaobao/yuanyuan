# 示例项目数据（虚构双章测试样例）

本目录提供完整的两章虚构正文测试对（《雾港回声》），不是用户真实小说，也不代表用户笔样/风格；用途是让使用者可以实际运行计数字数并对照跨作者文件如何衔接。两章均为独立纯正文文件，不含标题或审计标签：

- `第001章_演示正文.md`：2505个Unicode非空白码点。
- `第002章_演示正文.md`：2570个Unicode非空白码点。

两者字数由包内脚本复算；并未在真实GLM会话生成，也没有外部文学评审，不能据此宣称创作质量或审计有效。

## 锁定设定（演示用）

- 书名：《雾港回声》（虚构）
- 港区潮汐钟偶尔出现迟响；林遥只知道父亲留下的是铜钥匙，不知道它可能有什么用途。
- 沈岸只根据公开货票/仓区资料判断旧仓名；他没有看见林遥的钥匙，也不知其细节。
- 锁定版本：设定v1.0；写入者作者03；更新时间2026-11-22T10:00Z。

## 两章卡片摘录

- 第001章目标：林遥在封港前检查父亲账本指向的七号仓；POV林遥；结尾发现可继续追查的货票/仓区线索。不得揭示钥匙用途。
- 第002章目标：沈岸根据货票确认旧仓名曾并入灯塔物资间；他不能知道林遥手里的钥匙细节。结尾形成下一步查档计划。

## 审计问题记录的边界

下方`ISS-001`是**反事实教学示例**：假设另一版候选稿让沈岸在未见钥匙时说出用途，便应按下列方式登记。它不是上面两章正文中真实发生的问题，也不是已运行的作者07审计记录。

- ID：ISS-001；章节：002；严重度：阻断；轨道：连续性。
- 假设证据：替代候选稿段落“沈岸看见钥匙，认出它能开档案室”，与设定v1.0人物知识边界冲突（沈岸未看见钥匙，亦无此知识来源）。
- 修复责任：作者05；建议删去钥匙识别，只保留凭货票判断旧仓名。
- 复审：检查修改稿不再出现提前知情后关闭ISS-001；保留旧候选v0.1，修改稿另存v0.2，不覆盖。
