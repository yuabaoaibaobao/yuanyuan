# 执行规范｜作者08 每15章连续性审计

## L1 目的与风险

按1–15、16–30等固定闭区间窗口检查跨章剧情、人物弧光、伏笔、时间、战力/规则、信息释放与风格风险复发趋势。输出可定位、可复审的问题和下一步建议。15章周期是人工流程约定，不是研究验证的最佳频率；模型审阅可能存在同源偏差。

## L2 开工门槛

- [ ] 从项目工作区读取唯一`project_state.json`，核对状态版本、窗口边界、必要文件路径及版本/哈希。
- [ ] 按逐章清单读取窗口内章节正文/卡片、07审计记录、相关真值和变更、上期08报告、摘要回查指针及10号趋势；不能把未读材料写成已审。
- [ ] 逐章登记“已读/未读/不可读”。窗口版本冲突、关键证据缺失或边界不明时停止总判定，仅可给局部发现并列恢复动作。
- [ ] 超出可审阅范围时分批审阅，明确结论范围和未覆盖章节；不声称通读未读材料。

## L3 审计流程

窗口文件版本锁定 → 核对总纲兑现/因果、人物知识与弧光、伏笔、时间空间、规则/资源、章节功能 → 汇总07问题的复发/误伤/修复 → 对照上期报告和10号账本 → 形成逐章状态、问题ID和影响集 → 交责任者返修/用户裁决 → 复审并更新结论。

每项发现必须给章节/段落证据、对照真值或用户约定版本、严重度、问题ID、责任方、阻断状态和复审条件。区分事实冲突、可行动建议和主观偏好；不以检测器分数推断作者身份。

每项已批准canon变更都要列出影响集：变更ID/旧新值/真值版本/受影响章节或卡片/路径与版本。依赖旧真值的候选标`stale`并登记状态；阻断09放行。责任作者按新真值更新并由07重审，跨窗口影响由08复核；证据链清空后才可解除stale。

## L4 判定标准

窗口边界明确；每章有实际读取状态与版本；未读材料不写“通过”；问题可定位并连至责任者及复审证据；趋势结论列样本量和缺口；规则建议只标候选，不把15章频率、风格分数或模型自审说成实证结果。一般主观风格偏好不能单独阻断。

作者09仅在阻断和待用户裁决均为0、必需证据完整、受影响stale候选已复审清空时放行。关键事实、路径或版本缺失时，报告窗口不完整，禁止输出周期通过结论。

## L5 正反例

正例：窗口16–30，定位ISS-014在第18、24章两个独立段落复发，引用两处原文和有效风格约定，注明责任者、是否阻断和下一轮复审条件。反例：只凭第18章一个口头禅要求全书删除，未说明用户契约、样本范围或可能误伤。

## L6 收工与交接

- [ ] 报告记录窗口起止章、输入版本/哈希、逐章已读状态和缺项。
- [ ] 问题ID、证据、责任会话、阻断状态、canon影响集和stale清单完整。
- [ ] 结论只覆盖实际读取并核对版本的材料；受影响候选未清空时明确阻断。
- [ ] 状态JSON只向项目所有者提交更新建议；不越权写入唯一状态或真值文件。
- [ ] 交接包含未关闭ID、用户确认项、下一责任者及动作。
