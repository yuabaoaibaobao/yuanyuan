# GLM 多会话长篇小说创作技能包

## 部署对象与使用范围

本包用于智谱清言 GLM 项目：一个项目管理一部长篇小说。所有作者会话以项目文件区作为唯一跨会话状态通道；聊天上下文不互通。解压后先将本目录全部内容导入同一项目文件区，再把根级两份文件分别放入项目的自定义指令和长期记忆位置。

## 根级两文件与优先级

- `01_自定义指令.md`：项目级流程纪律，优先级最高，实测不超过2000字。
- `02_长期记忆.md`：作家人格与审美底色，实测不超过2000字；不覆盖流程纪律。
- 冲突裁决以根级01/02中定义的项目全局规则为准。基于用户已确认的C-07，作者会话指令不重复复制优先级句，避免多处维护产生不一致。

## 体量与章节批次契约

- 中篇：20–90万字；长篇：90–180万字；180万字为硬上限，超过拒绝继续并建议另立第二部/项目。
- 每轮两张章节卡对应两章正文；每章目标2500–4000字。章节卡是计划表，不套用正文篇幅。
- 计数采用Unicode非空白字符数；所有正文交付报告实际字符数与目标区间。

## 快速开始

1. 导入本目录中的文件到一个 GLM 项目。
2. 填入01自定义指令、02长期记忆。
3. 逐个建立作者01至作者10的独立会话，将对应`作者NN/会话指令.md`作为该会话指令或首轮规范，并上传该作者夹及项目共享状态文件。
4. 先在作者01说“继续”。作者01会多轮询问立项与笔样，未确认不会进入检索或创作。
5. 依作者流程表按序操作。日常章节循环：作者04两张卡→作者05两章→作者06去AI味与润色→作者07双轨审计→作者09定稿；每15章作者08审计，作者10记账与趋势反哺。
6. 每次收到流程表后，若无待确认/阻断，回复“继续”；项目文件缺失、版本冲突、用户门禁未过时先处理卡点。

## 作者流程与职责索引

| 会话 | 名称 | 主要交付 | 核心门禁 |
|---|---|---|---|
| 作者01 | 立项确认总控 | 口径/风格指纹/体量节奏契约/检索需求 | 关键需求用户确认 |
| 作者02 | 检索与研究枢纽 | 有出处检索回传、复用指引 | 来源可追溯，冲突待裁定 |
| 作者03 | 设定总控与全书规划 | 总纲/人物/世界/伏笔/时间线/知识边界/战力账本 | 简版及详细版两次确认并锁定 |
| 作者04 | 双章章节卡规划师 | 每批两张可执行章节卡 | 读取前两章及全部相关台账 |
| 作者05 | 双章正文创作 | 两章正文，每章2500–4000字 | 卡片、前文、设定、字数均核对 |
| 作者06 | 去AI味与润色 | 两章V1、修改证据、自评卡 | 保留笔样；不擅改剧情真值 |
| 作者07 | 双轨章节审计 | 剧情连续性审计 + AI味/风格保全审计 | 两轨通过且无待裁定才放行 |
| 作者08 | 每15章连续性审计 | 跨章报告、债务与进化建议 | 阻断项关闭前节点章不定稿 |
| 作者09 | 审计后定稿 | 正式正文、定稿索引、台账更新 | 07通过；节点章还需08通过 |
| 作者10 | 质量账本与健康报告 | 逐章记账、15章趋势、卷末/全书报告 | 数据有证据，报告可复算 |

## 文件流转原则

- 共享文件带版本、状态、来源和更新时间；不通过聊天转述交接。
- 审计问题用唯一ID贯穿发现、返修、复审、定稿和统计。
- 作者07的剧情与AI味问题回责任会话；作者08的15章发现进入作者10趋势，再回作者04/05/06形成有证据的改进规则。
- 规则进化有版本、适用范围、试行窗口和回滚条件；不得自动改用户风格指纹、人物/世界设定、体量契约或总体节奏。
- 每会话末尾必须输出简易流程表，明确完成、文件、门禁、下一站及用户是否需操作。

## 裁决与版本记录

- 01置于02之前：依原始需求顺序消歧，且01是全局流程纪律。
- 体量以用户后续明确答复为准：20–90万中篇、90–180万长篇、180万硬顶；替代上游初始10–200万建议。
- 每章2500–4000字为用户本轮再次明确的要求；两章正文与两张章节卡按批配对。
- 作者10按用户要求负责质量账本、每15章趋势、卷末债务总结和全书健康报告。
- 教程、导入检查单、故障排查表按用户要求外置于ZIP；不作为运行依赖。
- 每作者会话不重复写01>02>会话规范优先级句，项目级01/02定义全局规则（C-07）；本裁决优先于上游模板中旧版重复声明要求。

## 实测信息

- 01：934字；02：518字（全文Unicode非空白字符，含末行实测声明，均≤2000）。
- 包内文件数（不含manifest.json）：132；累计Unicode非空白字符：79567。统计含本README与P6验收报告；manifest另列并逐文件提供字节数、字符数与SHA-256。
- 原始造包总控Prompt实测30,953字符；`需求追溯表.md`按2.01–2.50逐行映射，并追加用户后续要求。
- UTF-8无BOM；Markdown/JSON纯文本，无外部插件和绝对路径依赖。
