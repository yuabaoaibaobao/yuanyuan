# GLM 多会话长篇小说创作技能包

> **版本 1.1.1｜使用边界先读**：这是面向 GLM 项目空间的文件化人工工作流，不是可自动调度、跨会话自动同步或平台能力认证。文件共享、目录保留、指令注入长度和上下文容量因产品版本/账号/入口而异；本仓库未获得用户账号，也未执行真实 GLM 项目端到端测试。请按「首次部署冒烟测试」确认本账号实际行为，不要把文字门禁误认为平台硬阻断。

## 1. 用什么、适合谁

每个项目建议只放一部长篇；完本后可归档并另开新项目，使用包内“项目迁移包”选择性继承设定。项目目标范围沿用已确认口径：中篇20–90万、长篇90–180万，合计20–180万字；每章正文必须为2500–4000 Unicode非空白码点（含标点，不含空白）；一个工作批次保留两张章节卡、两章正文。小、中、大三档的规划方式见`项目运行模板/项目规模与节奏表.md`，具体档位须立项时选定，不擅自改变单章字数和双章批次。

此包不承诺写作质量、特定模型输出长度、计费/耗时或平台项目文件区行为。作者01–10是人工切换的职责分工，不是十个会自动互相调用的Agent。状态只通过用户在项目文件区保存的文件交接；默认串行写入，不支持并发协作。

## 2. 文件的权威性

- `01_自定义指令.md`：项目流程约束；`02_长期记忆.md`：人格/审美原则。按用户项目实际支持情况分别粘贴或上传；平台是否完整保留/注入，必须冒烟测试。
- `作者01/`至`作者10/`：现行会话包。部署路径、拍平命名和确认步骤见本目录内`部署与运行手册.md`。
- `项目运行模板/`：状态JSON/Schema、Markdown视图、分卷大纲、权限矩阵、滚动摘要、质量进化索引和续作迁移模板。项目数据放入`项目工作区/`，该目录不进入发布清单。
- `工具/`：Python 3.9+ 标准库脚本，用于字数复算、SHA-256/ZIP清单验证；不会评价小说文学质量或自动拦截模型。
- `示例项目/`：含一对完整虚构演示正文（每章均2500–4000码点）、设定/章节卡摘录和状态索引示例；不是用户项目或GLM生成记录，不代表最佳文学写法。可用于实际测试字数工具与双章关系。
- `许可证.md`：本包原创说明性材料的使用许可；用户笔样和第三方资料不因此获得许可。
- 早期`调研留痕/`等材料已移至仓库根`维护记录/技能包研发档案/`和`造包过程存档/历史快照/`，仅用于追溯、不随ZIP发布，不能覆盖本包现行约束。历史版本说明已归档至维护记录。

三份用户指南按要求仍放在仓库`用户使用指导/`、不进入ZIP。ZIP内`部署与运行手册.md`提供离线部署所必需的说明，用户指南是补充材料，不构成运行依赖。

## 3. 快速开始

1. 先读`部署与运行手册.md`，按保留目录结构导入。若平台拍平文件名，按手册的前缀命名约定；先用一个空白测试项目验证上传、读取、保存与另一会话读取。
2. 安装 Python 3.9+（可选）。统计章节：`python 工具/字数统计.py 第001章.md --chapter-range`。验证本包：`python 工具/构建与校验.py verify`；运行定向检查：`python 工具/构建与校验.py lint`；回归测试：`python 工具/测试工具.py`；状态校验：`python 工具/validate_state.py <状态文件>`；摘要结构与覆盖校验：`python 工具/校验摘要.py <摘要文件> --chapters 1-15`；完整性`verify`与语义`lint`分开运行。
3. 将01/02配置到平台支持的位置，把作者01–10各自会话指令配置到对应会话。保留本包相对路径，或按手册生成扁平映射。将`project_state.json`复制到源包外的`项目工作区/`作为项目唯一结构化状态文件，按`state.schema.json`运行`python 工具/validate_state.py <状态文件>`；若文件记录/放行变更，附`--root 项目工作区`作真实路径和SHA核验。Markdown状态索引仅作可读视图。首次和每次实质状态更新后均校验。
4. 从作者01立项。确认书籍题材/目标读者/节奏形态、体量档位、章节约束、风格样本授权与保存边界。需要人工确认的事项由用户明确答复，不能把“继续”解释成批准。
5. 作者02检索、作者03确认设定和分卷大纲后，按人工流程串行运行04→05→06→07→09。两章作为同一批交付，但模型可分场景/分多轮生成；章节文件只在全文完成后合并统计。每15章由08审计；节点章未通过08不得由09锁定。作者10登记统计和周期报告。
6. 每一交接由用户将项目文件保存在源包外的`项目工作区/`，更新`project_state.json`的版本、文件路径、写入者、模型/规则版本、门禁和下个动作，再渲染/同步Markdown视图。任何不确定版本或并发编辑，先停下对照差异，不覆盖旧稿。

## 4. 双章、分段和15章节点

双章是规划/审计批次，不要求一次响应输出5000–8000字。作者05对每章分别建立正文文件；遇到单次输出限制时，按场景切分成可续写的小段，段段标注章节号、段号、场景目标和最后一段末句，不重复前段、不跨章串写。完成后去掉段标记合并，由脚本对最终章节纯正文文件复算2500–4000码点。分段期间不得让06/07/09将不完整章节当作完整稿。

第15/30/45章等节点按“闭区间前15章”审计：第15章完成07后，以1–15章候选稿进入08；同批第16章可继续按卡写作并保持候选状态，但在08报告通过前不得定稿/锁定。08审计报告明确窗口起止章、逐章状态和未关闭ID；通过后09分别放行15章与候选16章。其余章节依同样规则滚动。首批不足15章不触发08。

## 5. 规模、成本与运行预算

| 目标体量 | 建议规划档 | 章节估算（按2500–4000 Unicode非空白码点（含标点，不含空白）） | 双章批次数约 | 适用节奏参考 |
|---|---|---:|---:|---|
| 20–30万 | 紧凑型 | 50–120 | 25–60 | 主线集中，支线少，按需要分卷 |
| 30–90万 | 标准型 | 75–360 | 38–180 | 主要人物弧与支线并行，卷末闭环 |
| 90–180万 | 长篇型 | 225–720 | 113–360 | 明确分卷、滚动摘要、周期债务审计 |

估算为体量除以章节区间的范围，不是保证值；选定目标字数后按同一口径重算。人工交互数、模型额度、成本和日历工期取决于模型、输出限制、返修率和用户速度，未做可靠实测，本包不虚构数字。先完成两章试运行，记录实际轮数/返修/读取失败，再外推预算。长篇运行按每个双章批次保存检查点，可从状态索引所指的“下一动作”续跑。

## 6. 文件所有权、版本与返修终止

- 一份共享真值文件同一时刻只允许一个会话/用户作为写入者；该文件的所有者、当前版、上一版、变更理由和更新时间登记在状态索引。交接时先写新版本再切换索引，不覆盖已锁定稿。
- 本包不实现广播或文件锁。改设定须先建变更单，由用户裁决影响范围；交接接收者逐项确认已读取的新版本。确认回执写入交接包，不等同平台自动通知。
- 每个返修问题最多进行两轮责任会话修改+复审。仍未解决时改为`待用户裁决`，保留原稿与证据，不能无限自动往返；阻断问题不得降级放行。
- 每15章只提出质量规则候选。候选需有规则ID、至少两个独立章节例证、拟改善指标/可能误伤、试行窗口和回滚条件；由用户批准试行。比较样本不足时维持候选，不声称规则“已验证”。

## 7. 字数和项目字数累计口径

统一按Unicode非空白码点计数，标点计入、空白不计。作者05完成正文后可运行`python 工具/重复检测.py <章节文件>`做重复段落/近似片段提示；该检测只提示文本相似，不证明注水或抄袭，也不替代人工判断。此口径可由包内脚本复算，但不宣称等于任意平台编辑器/出版机构的“字数”。计数对象是章节纯正文文件，不含章节卡、标题、审计表或段落生成说明。用`字数统计.py`复算每章；作者模型自报仅作交接，不作为门禁证据。全书累计以已放行定稿版本的逐章计数相加，并在质量账本记源文件SHA-256或版本，不将返修旧稿重复计入。

构建新版时必须显式给输出路径；默认禁止覆盖已存在ZIP或manifest。示例：`python 工具/构建与校验.py build --output ../GLM多会话长篇小说创作技能包.zip --manifest-output manifest.json --overwrite`。先备份现有ZIP和manifest，再使用`--overwrite`。

## 8. 维护与验证状态

此版本提供可重复的文件/清单/哈希/ZIP校验和示范数据校验；不等于真实GLM项目端到端验证。报告须区分“静态自动检查通过”“人工审阅”“真实平台试运行”“文学质量判断”，无证据的项目写“未验证”，不得填“通过”。发生本包升级时保留旧ZIP和旧项目状态快照；先对新旧模板做差异审阅、备份用户项目、按`部署与运行手册.md`迁移，再更新manifest/ZIP。旧项目继续用旧包，除非明确迁移。
